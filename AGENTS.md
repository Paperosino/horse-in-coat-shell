# Инструкции разработки hics

Этот файл действует для всего репозитория. Он фиксирует требования пользователя и уроки разработки; это не список обещаний, что каждая функция уже реализована. Прямые текущие указания пользователя имеют приоритет. Перед изменением проверяй реальное состояние кода и документов: старое описание ошибки не доказывает, что она существует сейчас.

## 1. Продукт и границы

- Публичное имя оболочки и команд — **hics**, проект — horse-in-coat-shell. Новые команды, настройки, сервисы и документация используют hics. Благодарности, лицензии и исторические имена сторонних проектов сохраняются. Старые внутренние имена и совместимость мигрируют контролируемо, без слепой глобальной замены ABI, QML URI, IPC и сохранённых данных.
- Цель — полноценный рабочий стол: понятный новичку, глубоко настраиваемый для опытного пользователя Linux.
- **Не создавать собственный файловый менеджер, магазин приложений или службу техподдержки.** Интегрировать Nautilus, Dolphin и другие установленные ФМ, их архиваторы и существующие системные средства. Помощник локальной диагностики допустим; это не техподдержка.
- Не переписывать зрелые механизмы хранения секретов, PAM, пакетов, Bluetooth, печати, прошивок и резервного копирования. Использовать существующие API/службы и честно показывать ограничения.
- Новая функция должна иметь законченный пользовательский сценарий, обработку ошибок и настройки там, где они нужны. Кнопка, которая лишь показывает успешный toast без результата, недопустима.
- Не объявлять полной совместимость восстановления GNOME/KDE, если поддерживаются только общие desktop/autostart данные. Нельзя обещать восстановление внутренних документов/вкладок произвольного приложения без его API.

## 2. Как работать

- Общаться с пользователем по-русски, если он не попросил иначе. Объяснять результат и ограничения простым языком.
- Выполнять уже разрешённую работу до конца: код, необходимые проверки, документация и установка, если она запрошена. Не спрашивать повторно разрешение на обратимые действия в согласованных рамках.
- Не переносить согласие на прошлую конкретную опасную операцию на любые будущие действия. Пароли из диалога никогда не помещать в исходники, инструкции, shell-команды, логи, тесты или коммиты.
- Перед правками читать `git status`, относящийся к задаче код и документацию. Не откатывать чужие изменения и не смешивать их со своими.
- Искать через `rg` / `rg --files`. Проверять регистр путей: `shell/services` и `shell/Services`, `components` и `Widgets` сосуществуют и не взаимозаменяемы.
- Не строить решение только по предложенному пользователем эссе или примеру. Проверять протоколы, реальные API, версию зависимостей и фактическое поведение по первичной документации/исходникам.
- Не приводить неподтверждённые проценты ускорения, FPS, RAM или задержки. Отличать измерение, расчёт, предположение и аппаратно не проверенную функцию.
- Итог: что изменилось, что проверено, что установлено, какие действия требуются пользователю. Не называть синтетический сценарий естественным воспроизведением редкого пользовательского бага.

## 3. Карта проекта и версии

- `shell/`: интерфейс Qt Quick/QML, сервисы состояния, компоненты и ресурсы.
- `shell/plugin/`: C++ QML backend и интеграции Qt; `native/system/`: привилегированный системный брокер и помощники; `native/desktop/`: пользовательские службы.
- `native/hyprbars/`: оформление, ввод, стакинг и обзор; `native/render-dispatch/`: общий диспетчер рендера; `native/motion/`, `native/capture/`: нативные расширения.
- `third_party/phantomat/`: поставляемый холст. Это часть рабочего стека; изменения требуют совместных проверок с hics-bars и общего render-dispatch.
- `shell/assets/hyprland/layouts.lua` и конфигурация рядом: политика режимов и IPC композитора.
- `distribution/`, `packaging/arch/`, `install.sh`: установка, системные юниты, runtime и пакет. `tests/`: unit, mock D-Bus, интеграции и замеры.
- На момент создания инструкции закреплён **Hyprland 0.56.2**; версия и ABI проверяются сборкой. Не переносить API из другой версии наугад. При обновлении версии пересмотреть это правило и весь набор нативных проверок.
- C++23, CMake ≥ 3.27, Qt ≥ 6.9, Python ≥ 3.11; пакет использует частные Quickshell/Qt. Актуальные требования находятся в CMake и PKGBUILD.
- Использовать существующую конфигурацию сборки. Для новой сборки следовать `INSTALL.md`; не уничтожать build/cache ради мелкой правки.

## 4. Интерфейс и визуальный язык

- Все страницы, диалоги, виджеты и новые функции должны выглядеть частью оболочки: её палитра, типографика, Material Symbols, радиусы, токены размеров, отступы, поверхности, мембраны/блобы и анимации.
- Предпочитать существующие Styled-компоненты, карточки и общие контролы. Не добавлять случайные белые системные элементы или отдельный визуальный язык.
- Структуру настроек строить по задачам и логическим категориям, с понятными подпунктами и переходами, близко к логике Параметров Windows 11. Не копировать буквально внешний вид Windows.
- Повседневные действия видны сразу; технические параметры, редкие протоколы и детали — в расширенных настройках. Глубокая настройка сохраняется, но не превращает основную страницу в бесконечный набор строк.
- Не дублировать одну настройку в нескольких независимых разделах. Быстрый переключатель и подробная страница используют один источник состояния. Панель виджетов и иконки состояния не должны конкурировать за одно управление.
- Строки и карточки адаптивны: длинные переводы не выталкивают кнопки за край. Проверять узкую ширину, масштаб, несколько экранов, крупный текст, высокий контраст и reduced motion.
- Использовать реальные имена глифов из поставляемого шрифта. Не допускать вывода текста вроде `TOUCHPAD` вместо иконки.
- Живое обновление модели не пересоздаёт страницу, не сбрасывает scroll, раскрытые секции, выбор и введённые данные. Обновлять стабильные записи по идентификатору.
- Поиск должен реально фильтровать локали/настройки/приложения. Ошибки применения видны и объяснимы; ожидающая операция не изображается завершённой.
- Все popup/context menu/история буфера закрываются по клику снаружи и Escape. Нажатие внутри не закрывает меню раньше действия; невидимые поверхности не перехватывают ввод.
- ПКМ по панели, её виджету и рабочему столу должен давать относящиеся к объекту действия и переход в нужный раздел настроек.
- Размер панели настраиваемый. Сетка рабочего стола и развёрнутые окна учитывают фактическую work area, положение, масштаб и зарезервированную область панели/дока.
- Виджет сети ограничивать по высоте: до десяти строк, далее прокрутка; быстрые VPN-подключения и переход в настройки сети обязательны в соответствующем сценарии.
- Первый запуск: полноэкранный последовательный тур с пропуском, читаемыми кнопками и рабочей прокруткой. Демонстрации компактны и качественны; записи реальной оболочки соответствуют локали, синтетический прототип не выдаётся за запись.
- Блокировка панелей/хоткеев в туре должна сниматься при завершении, пропуске, ошибке и аварийном восстановлении. Проверять локаль, несколько раскладок и переключение языка с первой минуты.

## 5. Анимации, док, уведомления

- Плавность и низкая задержка важнее количества эффектов. Не добавлять искусственные задержки в обработку ввода. Reduced motion действительно отключает лишнее движение.
- Док: стабильная ширина, непрерывная волна подъёма без распирания по X, мембрана охватывает поднятые иконки. Блоб следует форме/позициям иконок, а не просто координате курсора.
- Базовый слот под иконкой и вся поднятая/масштабированная иконка кликабельны. Учитывать трансформации, clipping, scroll viewport, четыре стороны дока и масштаб UI.
- В доке уже введён единый маршрутизатор `raisedInput`. Не возвращать перекрывающиеся MouseArea на слотах/поднятых иконках: они отбирали части кликабельной области. На время press/release границы ввода фиксируются; Wayland input region совпадает с маршрутизатором, а не только с нарисованной мембраной.
- Проверять квадранты, центр, соседние иконки, press во время затухания волны, drag, wheel, анимации off и кнопку приложений по обоим краям.
- Меню приложения показывает список его окон с переходом, закрытием и принудительным завершением. Не рисовать неработающие кнопки рамки в списке.
- Превью в меню дока появляется после **1 секунды** наведения; после первого показа переключается сразу. При уходе действует существующий настраиваемый/реализованный период сброса прогрева; после него снова нужна задержка. Превью визуально связано с меню блобом.
- Превью тестировать на внешних Wayland, X11, GTK и Qt окнах: работа только на окнах самой Quickshell недостаточна. Не оставлять пустую тёмную карточку при ошибке захвата.
- Сворачивание в стакинге доходит точно до иконки приложения; обратная анимация согласована с готовностью реального буфера окна. Не показывать долго пустой силуэт после окончания восстановления. Иконка реагирует на поглощение, геометрия, контент и мембрана синхронизированы.
- Уведомления и другие popup правой верхней области используют общий механизм размещения/блобов: не накладываются друг на друга и не оставляют пустой блоб отдельно от содержимого.
- Действие уведомления может открыть конкретный диалог приложения, но это ещё не означает фокус/переход к окну. Проверять оба результата, в том числе для уже запущенного приложения.

## 6. Окна, декорации, ввод и холст

- Единственный источник CSD/SSD — `native/hyprbars/decoration-policy.cpp`. Сохранять ручные переопределения, включая разные режимы окон. Внутри редактора правила нужен выбор приложения/типа окна из открытых окон, а не отдельный несовместимый механизм «правило для окна».
- **Не возвращать списки классов приложений для определения CSD/SSD.** Геометрия теней, отсутствие xdg-decoration, вызовы move/resize, opaque region и нулевые frame extents не являются доказательствами наличия собственного заголовка.
- Для Wayland учитывать согласованный xdg-decoration и legacy KDE protocol; режим применяется после ack_configure и commit. Для X11 — корректные Motif flags, TITLE и ALL. `_NET_FRAME_EXTENTS` — результат работы WM, не запрос клиента.
- Не путать popup с dialog/transient: модальное или дочернее окно не обязано быть без рамки. Неуправляемые X11 и настоящие popup-роли обрабатывать отдельно.
- Ручное show/hide заголовка и decorate — разные эффекты. Принудительный SSD не может удалить произвольный DOM/HeaderBar клиента; сообщать границы настройки честно.
- Когда SSD скрыт, нативные move/resize/maximize/minimize/close клиента остаются рабочими. Не перехватывать всё полотно приложения как предполагаемый заголовок. Двойной клик не заменять переключением floating.
- GTK получает количество, порядок и сторону кнопок через существующий механизм настроек/портала. Проверять GTK3, GTK4 и libadwaita, в том числе наличие minimize в стакинге.
- При выходе fullscreen → maximized в стакинге пересчитывать work area с учётом дока; не использовать устаревшую геометрию fullscreen.
- Фокус хранится согласованно в desktop state, Wayland seat и XWM. Для смены поверхности использовать стандартный `rawSurfaceFocus`/подходящий API, а не только `setKeyboardFocus`.
- `keyboard-focus.hpp` восстанавливает освобождённый seat после перехода и страхует первый keypress X11. Нельзя красть фокус у интерактивного слоя/поля, другого приложения, seat grab или lock screen. Проверять обычную X11 модель и `WM_TAKE_FOCUS`.
- Холст не должен ломать собственную прокрутку приложений (включая MAX), ввод, CSD drag/resize и X11 клавиатуру. Координаты pointer, input mask, preview и render должны совпадать после масштабирования/перемещения камеры.
- Возврат к окну через док/уведомление/навигацию восстанавливает его видимую позицию и совместное размещение, а не всегда центрирует его. После закрытия активного окна переходить к последнему доступному активному окну.
- Память групп/деления очищается при закрытии окон и перестраивается при изменении порядка. Адрес/указатель без стабильного id не использовать как долговечную идентичность.
- Реестры протоколов привязаны к lifetime ресурса; учитывать уничтожение, переиспользование адреса, поздний callback и смену поколения состояния.
- `drawTex` патчит **один общий render-dispatch**. Не устанавливать конкурирующие trampolines из canvas и bars, не передавать владение Lua-перещёлкиванием машинного кода.
- Не расширять `#define private public`; предпочитать публичный API/проверенные символы закреплённой версии. Не считать ручные объявления полей и методов универсальным ABI.

## 7. Архитектура, ресурсы и асинхронность

- Предпочитать C++ сервисы/помощники для постоянно работающих интеграций, больших данных и горячих путей. Python допустим для редких задач, когда перенос не даёт доказанного выигрыша. Не переписывать всё ради языка.
- Предпочитать D-Bus/libnm/PipeWire/API и прямое QFile-чтение вместо множества `sh`, `cat`, `nmcli`, `hyprctl`, `nvidia-smi`. Один источник сетевого состояния, без параллельных monitor-процессов.
- Сигналы и файловые наблюдатели вместо частого polling. Объединять всплески событий, пакетировать IPC, кэшировать с явной инвалидацией. При атомарной замене файла переустанавливать watcher/следить за каталогом.
- Не запускать branding migration Python при каждом CLI, если быстрый проверенный маркер позволяет пропуск. Не удалять совместимость до завершения миграции данных.
- UI/render thread не ждёт диск, сеть, внешнюю команду или длительный D-Bus. Рекурсивный поиск, LRC, картинки и крупный clipboard обрабатываются асинхронно с лимитами размера, обхода и отменой.
- У каждой очереди запроса busy охватывает чтение и callback, а не только жизнь процесса. FailedToStart, пустой ответ, ненулевой код и таймаут завершают запрос и освобождают очередь.
- Поздний ответ не перезаписывает новый выбор; использовать id/generation/cancellation. Сброс настройки удаляет ожидающую debounce-запись старого значения.
- Завершение объекта отменяет работу и безопасно завершает/дожидается принадлежащих ему задач; фоновая задача не захватывает разрушенный QObject. Проверять выход и перезагрузку QML во время операций.
- Не применять sleep для синхронизации lifetime, PipeWire shutdown или готовности композитора. Использовать wakeup, join, readiness и ограниченные ожидания. Qt API и ожидания потоков нельзя вызывать из POSIX signal handler; использовать безопасный канал в event loop.
- Watchdog должен следить за event loop, D-Bus broker — иметь ограниченные очереди и справедливые лимиты клиентов, с очисткой статистики. Hardening не должен запрещать сервису необходимые дисковые/системные операции.
- CUPS thread-local server/user задавать явно для каждой операции; состояние worker-пула не должно зависеть от предыдущей задачи. Общие мутации сериализовать там, где необходимо.
- Освобождать подписки неиспользуемых виджетов/аудио, GPU surfaces и промежуточные framebuffer. Не создавать скрытый PanelWindow на каждое уведомление ради image resize: использовать QImageReader/фоновую задачу и общую инфраструктуру.
- Сетевые ответы, файлы, история, кэши и журналы ограничены по объёму. CookieJar переиспользуется по политике сессии; fuzzy-search caches имеют инвалидацию/лимиты. Анализ обоев не работает без потребителя.
- Кэш GPU учитывает монитор, размеры, scale, цветовое пространство, параметры, live wallpaper и изменение контента; static cache не замораживает живые обои. Снижение разрешения/FP16 допустимо только после проверки цвета и качества.
- В горячем пути мыши избегать O(число окон) callbacks и hit tests. Ранний выход для constrained pointer/session lock; по возможности один маршрутизатор событий.
- Микрофризы проверять в простое и под нагрузкой: таймеры, fork/exec, GPU sampling, I2C/DDC, перепубликация моделей, perpetual frame requests. Не лечить их постоянным 60 FPS циклом.

## 8. Игровая производительность: проверять, а не копировать рецепты

- Обычный режим сохраняет качество, эффекты и частоту экрана. Не занижать 165 Гц до 60 Гц и не ухудшать визуал под видом оптимизации. Снижение эффектов — явный игровой/адаптивный режим и его настройки.
- У каждого изменяемого параметра один владелец. GameMode сохраняет реальные исходные значения и восстанавливает только свои изменения, включая reload, аварийный выход и смену активного окна.
- Нативный Wayland клиент сам по себе не игра; запущенный Steam тоже не означает активную игру. Использовать проверенный детект и ручные исключения.
- Уменьшать фоновые polling/визуализацию в игре. NVIDIA sampling через NVML, если доступно; не создавать постоянные CLI процессы на каждом тике.
- Direct scanout зависит от композитора, драйвера, overlays и буферов. Прозрачность/пустая input mask не гарантирует отсутствие mapped layer. Учитывать конкретный монитор, явно вызванный UI и приватность/lock; не обещать гарантированный scanout или конкретные миллисекунды.
- VRR и tearing — разные настройки. VRR только по разрешению пользователя, с быстрым откатом при мерцании и проверкой монитора; пять секунд без жалобы не являются доказательством совместимости.
- CPU/power изменения, приоритеты и приостановка drain памяти должны иметь ограниченное время жизни и восстановление. Не выставлять CPUQuota всему user.slice ради ускорения игр.
- Запрещены busy-wait frame pacing, выдуманные sysctl вроде глобального tcp_nodelay, запись polling rate в USB power/control, плановая очистка drop_caches/compaction как универсальное ускорение, изменение чувствительности мыши под видом input batching.
- Не использовать Hammerspoon `hs.*` как API Hyprland. Проверять существование Lua/Hyprland параметров для закреплённой версии.
- Предиктивная загрузка не должна тайком запускать полноценные приложения и убивать их через минуту. Предпочитать безопасный ограниченный prefetch с бюджетом CPU/RAM/IO, cooldown и отключением в игре.
- Не обещать выигрыш от texture atlas поверх уже существующего Qt batching без профилирования. QML cache и QSB shader cache — разные вещи; использовать штатную сборку, не выдумывать qt-cachegen сервисы.

## 9. Системные интеграции и безопасность данных

- Внешние команды — массив argv без shell, когда shell не нужен. Интерфейсы сети, пути, заголовки окон, имена профилей и команды пользователя не интерполируются в `sh -c`/Lua без валидации и корректного кодирования.
- Имена сетевых интерфейсов валидировать; sysfs читать напрямую. Ошибки NetworkManager представлять понятным сообщением, сохраняя техническую причину для диагностики. Уже неактивное соединение при отключении — согласовать состояние, а не показывать необработанный D-Bus traceback.
- Нет Wi-Fi устройства — показывать Ethernet, а не «Wi-Fi отсутствует» вместо состояния сети. VPN: secret agent, просмотр/редактирование/удаление профиля, плагины протоколов, DNS, секреты и отмена подключения проверяются вместе.
- Captive portal использует состояние connectivity и безопасное явное окно авторизации; не путать ограниченную сеть с полным успехом.
- HTTP не использовать для геолокации/чувствительных метаданных, если есть подходящий HTTPS источник.
- Секреты — libsecret/Secret Service и существующая связка ключей, разблокировка через штатный login/PAM. Polkit разрешает административное действие, но не расшифровывает чужой keyring. Не логировать пароли, токены и содержимое приватного clipboard.
- Приватность: различать обнаружение использования камеры/микрофона и реальное принуждение запрета. Не обещать полную изоляцию обычных приложений настройкой Flatpak; явно показывать границы AppArmor/portal/обычного процесса.
- Изменения пользователей, пакетов, накопителей, прошивок — через существующие службы, polkit и проверенные операции. Не писать passwd/shadow вручную, не обходить проверки питания fwupd, не форматировать и не менять реальные разделы для теста.
- Очистка/backup/удаление пакета имеют конкретный объект, понятные последствия, ошибки и прогресс; не удалять произвольные каталоги по непроверенному пути. Удаление приложения не подразумевает удаление личных данных.
- Фоновые операции имеют общий центр с прогрессом, отменой, результатом/повтором и автоматически появляющийся виджет панели. Отмена не должна имитировать откат уже необратимого действия.
- Презентация временно управляет уведомлениями, сном и личным контентом и восстанавливает предыдущие настройки, а не жёсткие defaults.
- Настройки питания различают AC/батарею, sleep/lock/display timeout, крышку и внешний монитор. Не заменять всё одним power profile.
- ZRAM/ZSwap/smart policy валидируют пороги/размеры и реальные возможности ядра; zswap требует backing swap и не является произвольным дополнительным RAM. Не выполнять тяжёлый swapoff/drain во время игры без необходимости.

## 10. Темы GTK/Qt и внешние приложения

- Оболочка управляет темой через существующие палитры и настройки стеков; установка не должна требовать ручного скрипта для каждой программы.
- Проверять GTK2/3/4, libadwaita, Qt5/6 и Flatpak, светлый/тёмный режим и приложения с принудительно светлой базовой темой. Одной тёмной шапки недостаточно.
- Проверять фон, кнопки/состояния, popup, tooltip, file chooser, CSD header, separator и search/action bars. У popup не должно быть чрезмерной непрозрачной подложки, перекрывающей контент.
- Remmina выявила отдельный фон **`searchbar > revealer > box`**; тематизировать семантические GTK узлы, а не маскировать один класс приложения. Однопиксельная граница не равна светлой полосе-контейнеру.
- Сохранять пользовательские предпочтения и обновлять только управляемые значения/блоки атомарно. Тема оболочки должна доходить и до вновь установленных Flatpak.
- Внешним приложениям не передавать частные `QT_PLUGIN_PATH`, `QML_IMPORT_PATH`, `LD_LIBRARY_PATH` и несовместимые Qt библиотеки оболочки.

## 11. Запуск приложений, установка и обновление

- `.desktop` запускать через GIO/существующий ApplicationCatalogue. Не разбирать Exec пробелами вручную; учитывать field codes, Path, Terminal, TryExec, DBusActivatable и environment wrapper.
- Изменения desktop базы отслеживаются; каталог/иконки/поиск обновляются после установки и атомарной замены файла. Не кэшировать навечно несуществующий ярлык.
- Приложения запускаются в отдельных пользовательских scopes. Restart/crash любого сервиса hics не закрывает их. `hic-session.service` сохраняет `KillMode=process`; не возвращать уничтожение общей control-group.
- Принудительное завершение адресуется реальному процессу/группе приложения с проверкой идентичности; не убивать shell/systemd/другие приложения по устаревшему PID. Зависшая запись дока не должна сохраняться после закрытия окон.
- **Никогда не выгружать/перезагружать нативные Hyprland плагины в рабочем композиторе пользователя.** Обновить файлы и сообщить о необходимости нового сеанса. Тестировать загрузку/выгрузку только во вложенном композиторе.
- Нельзя пересобирать/перезаписывать `.so`, отображённый в память работающего теста. Тест сначала копирует бинарники в свой временный каталог.
- Пакет содержит обязательные зависимости, systemd/D-Bus/polkit ресурсы, Qt runtime (включая реально используемые модули, например Concurrent) и нативные манифесты. Альтернативные ФМ/архиваторы/прочие optdepends не устанавливать все одновременно.
- `packaging/arch/PKGBUILD` — источник зависимостей для установщика. Обновлять pkgrel при новом пакете. Проверять `install.sh --dry-run`, готовый пакет и первый запуск.
- Сборка обычным пользователем, root только для необходимых операций установки. Не делать `pacman -Sy`, не навязывать downgrade, полное обновление ОС или изменение сторонних сервисов.
- Включать собственные системные и пользовательские службы: `hics-system`, `hics-memory`; `hic-session`, `hics-desktop`, `hics-displays`, `hics-configuration`. TTY/chroot и отсутствие live user bus обрабатывать без ложной ошибки; запуск при подходящем входе.
- Использовать CMake install dirs/configure_file для путей юнитов; не хардкодить `/usr/bin` при поддержке другого prefix. Не мутировать исходники во время конфигурации.
- Не хардкодить `/home/paperos`, UID 1000, личный монитор, пути Downloads и временные каталоги сборки в продукте. Использовать XDG/HOME и определение устройств.
- Не заменять пользовательские monitor/local config. Сохранять исходную частоту, раскладки, scale и расположение; безопасное применение мониторов имеет подтверждение и таймер отката.
- Публичная установка не должна зависеть от локального staging-каталога разработчика. Временные способы перепаковки — только локальный инструмент, не канонический installer.
- При изменении startup устранять гонку readiness/IPC, а не увеличивать слепой `sleep 3`. Учитывать ABI и безопасность динамического загрузчика, а не считать появление сокета доказательством готовности всех подсистем.

## 12. Проверки и завершение задачи

- Подбирать проверки по изменённому поведению; не считать просмотр кода или компиляцию тестом пользовательского сценария. Не добавлять тесты, лишь повторяющие реализацию.
- Unit/mocks для D-Bus, авторизации, ошибок, валидации, очередей, таймаутов, lifecycle. Не трогать реальные VPN, диски, пользователей, firmware и backup пользователя для проверки.
- UI/input — во вложенном Hyprland с отдельными XDG, временными файлами, virtual pointer/keyboard и гарантированной очисткой дочерних процессов. Не вводить тестовые клавиши в host session.
- Использовать существующие тесты, например:
  - `python3 -m unittest discover -s tests -p 'test_gtk_theme.py'` — палитры;
  - `python3 tests/integration_gtk_palette.py` — реальные GTK узлы и снимки;
  - `python3 tests/integration_dock_pointer.py` — док/меню/превью/клики;

  - то же с `HICS_TEST_GLOBALLY_ACTIVE=1` — модель WM_TAKE_FOCUS;

  - `python3 tests/integration_decoration_policy.py` — переговоры и lifetime декораций.
- Перед запуском читать требования теста; некоторые требуют собранных бинарников/сессии/пакетов. Вспомогательный плагин `keyboard-focus-fault` предназначен только для тестового композитора и не устанавливается пользователю.
- Проверять не только обычный путь: быстрые повторные действия, reload, закрытие окна/объекта во время запроса, отмена, отсутствие устройства/бинарника, старые ответы, выход процесса и восстановление после ошибки.

- После установки: версия пакета, совпадение установленных файлов со сборкой, собственные службы, `hyprctl configerrors`, новые QML/сервисные ошибки, выживание ранее открытых приложений. Не заявлять, что warnings отсутствуют, если они есть.

- Проверять `git diff --check` и список файлов. `.gitignore` использует allowlist: новый исходник/документ может оказаться невидимым Git. Добавить узкое исключение, не открывать генераты, секреты, личные конфиги и артефакты сборки.
- `DE_ROADMAP.md` намеренно локальный/игнорируемый; не публиковать его автоматически. Публичные описания и состояние функций обновлять в соответствующих отслеживаемых документах.
- Коммит/пуш выполнять, если это разрешено задачей/пользователем; не объявлять push до успешного ответа remote.

## 13. Документы для продолжения

- `INSTALL.md`, `MAINTENANCE.md`: установка, обновление, восстановление и сервисы.
- `CONFIGURATION.md`, `DESKTOP_FEATURES.md`: настройки и пользовательское поведение.
- `docs/WINDOW_DECORATIONS.md`: протокольная политика, ручные overrides, X11 focus.
- `docs/STABILITY_AUDIT.md`: найденные гонки, проверки и исторические измерения.
- `docs/DE_PLATFORM.md`, `docs/DE_SERVICES_IMPLEMENTATION.md`: платформенные интеграции и их реальные границы.
- `docs/DESKTOP_ICONS.md`, `docs/INFINITE_CANVAS.md`: рабочий стол и холст; концепт не считать автоматически законченной реализацией.
- Quickshell при динамической загрузке QML по URL требует регистрации локальных зависимостей: отложенный тур сохраняет импорт каталога onboarding, иначе DemoCard недоступен. Проверять первое открытие, а не только отсутствие ошибок при старте. Type=simple/systemd blame не измеряет появление панели; подготовку, QML load и первый кадр измерять раздельно.
- Корневой shell.qml копируется CMake в build/qml/shell.qml при конфигурации: перед упаковкой изменения корня требуют повторной конфигурации, а не только cmake --install. Проверять совпадение источника, сгенерированного и установленного файлов. После изменения схемы C++ Config пересобирать все зависимые модули; не перезаписывать библиотеки запущенного QML-теста.
- Счётчики дока: использовать LauncherEntry с desktop id и временем жизни D-Bus-отправителя; история уведомлений — только явно обозначенный fallback. Портальные разрешения не являются общим sandbox обычных приложений. Визуальные ограничения AppArmor допустимы через поддержанный local-include, без угадывания структуры произвольной политики.
- Для текста Qt Quick без хинтинга под трансформациями использовать QtRendering с antialiasing: NativeRendering масштабирует готовую растровую надпись и даёт размытие. Размеры QFont сохранять через pointSizeF/setPointSizeF без округления в FontBuilder. Для масштабируемых иконок использовать ScalableIcon, заранее рассчитанный предел увеличения и mipmap; не менять sourceSize каждый кадр hover. У recolour-layer также должна быть подходящая textureSize с учётом DPR. Размер плашки и текста счётчика связан с размером иконки дока. Превью и его блоб раскрываются вместе, input/dismissal следуют видимой геометрии.
- При новых найденных особенностях обновлять этот файл: конкретный инвариант, причина и способ проверки. Не превращать его в журнал временных PID, паролей, локальных команд упаковки или неподтверждённых диагнозов.

- Сглаживание внешних приложений задаётся через управляемый Fontconfig-файл, GTK Settings/GSettings и Xft resources; не менять DPI или семейства шрифтов. Flatpak получает приватную копию без новых filesystem grants; проверять symlink границы. Не обещать принуждение собственного растеризатора приложения.

- Политика шрифтов управляется appearance.font.antialias/hinting; FontBuilder сохраняет стратегию исходного QFont. QtRendering не применяет хинтинг: при его запросе или отключении AA использовать NativeRendering. Изменения публикуются общим FontRendering с debounce и повтором последнего запроса, без фонового polling. Проверка: HICS_TEST_FONT_RENDERING=1 python3 tests/integration_settings_design.py и тесты FontBuilder/GTK.

- GTK4 >= 4.16 требует gtk-font-rendering=manual для явных параметров AA/хинтинга; GTK4 предпочитает портал файлу settings.ini. Проверять GTK на приватном D-Bus без activation directories, чтобы тест не читал настройки портала реального пользователя. GSettings font-rgba-order не принимает none: grayscale задаётся font-antialiasing отдельно.

- Material Symbols — графика, а не текст: MaterialIcon всегда QtRendering + AA, icon QFont tokens всегда PreferAntialias + PreferNoHinting. Пользовательское отключение AA/хинтинг текста не должно ухудшать иконки. Проверять неизменность растра значка для всех сочетаний политики текста.

- Защита запуска: shell_recovery ограничивает журнал аварий, выбирает отдельный recovery/shell.qml после двух сбоев за 120 секунд; чистый restart/logout не является сбоем. Резервный интерфейс не должен импортировать Config/обычные services или запускать branding migration. Проверять фактический distribution/bin/hics-shell, а не только mock команды runner.
- Рабочая точка запуска отделена от последнего автоматического snapshot. Продвигать только неизменившийся кандидат после первого кадра и ограниченной IPC-проверки; это не доказательство исправности всех виджетов. Откат использует существующий configuration guard, без второго постоянного демона. Восстановление из recovery переживает намеренный restart, но сохраняет deadline подтверждения.
- Повреждённые конфиги переносить в приватный карантин без readAll и без перекодирования исходных байтов. Учитывать shell-tokens.json, а не только legacy tokens.json. Не выдавать safe shell за восстановление композитора или lock screen; блокировку нельзя обходить.

- Массовые fault tests запускать с приватными HOME/XDG и недоступными реальными session/system bus. Пропуск из-за отсутствия user systemd/Wayland остаётся незакрытым gate, а не зелёным покрытием. При строгом umask fixture должна явно задавать исходные права перед проверкой сохранения permissions.
- QDBusPendingCallWatcher может быть уже завершён при создании. Подключение finished само по себе недостаточно: обработать isFinished через event loop и защитить callback от двойного выполнения и удаления owner. Не оставлять busy/pending навсегда при ServiceUnknown/недоступной шине.
- Стенд CachyOS: tests/vm_cachyos.py и vm_bootstrap_cachyos.sh, журнал docs/RELIABILITY_CAMPAIGN.md. Все диски/ключи/логи — вне Git, только виртуальные устройства. Не применять guest debug-shell или sudo policy к хосту.

- Журналы восстановления открывать с O_NOFOLLOW/O_NONBLOCK, проверять fstat и ограничивать чтение: FIFO вместо JSON не должен блокировать вход. Рабочая точка отвергает NaN/Infinity так же, как кандидат. Проверка — test_shell_recovery.py.
- Первый вход HICS использует hics-start и отдельные defaults; чужой Hyprland конфиг не заменяется. Публикация отсутствующих файлов атомарна и не перезаписывает конкурирующее создание; проверить первый/повторный вход и install prefix с пробелами фактическим запуском desktop entry.

- В отдельном recovery entrypoint Qt.resolvedUrl("../assets/…") выходит за корень Quickshell и превращается в qrc:/qs-blackhole. Helper вызывать через нативный Quickshell.shellDir + "/../assets/…", без импорта обычных services. Проверять integration_shell_recovery.py с реальным helper/guard, а не только подставным JSON; stderr и пустой ответ должны давать различимую ошибку.
- Сеанс запускает start-hyprland -- --config, а не Hyprland напрямую: это штатный watchdog закреплённой версии. Обычный и recovery QML имеют AppId org.hics.Shell с установленным desktop metadata для portal Registry. UPower/RealtimeKit — явные runtime-зависимости; не считать наличие на машине разработчика доказательством состава пакета.

- Таймаут IPC относится ко всему запросу: последовательные recv с заново выставленным timeout позволяют медленному клиенту бесконечно откладывать independent rollback. Использовать абсолютный monotonic deadline; integration_configuration.py проверяет trickling client.
- Главный наблюдаемый Hyprland Lua-конфиг не должен жить в заменяемом пакетном файле: pacman может удалить его между autoreload и повторной публикацией. hics-start создаёт частную точку запуска без перезаписи существующих настроек. Проверять исчезновение пакетной копии и обновление в настоящей ВМ; не лечить это горячей перезагрузкой нативных плагинов.

- StyledWindow должен назначать Config.screen/Tokens.screen и самому proxy window, и contentItem: размеры корня иначе берутся из глобального профиля, хотя дети используют настройки монитора. integration_window_tokens.py проверяет разные реальные значения.
- При уничтожении QML-делегата id внешнего делегата может стать null раньше пересчёта дочерней геометрии. Не читать disk.modelData без guard в размерах/моделях разделов. Lifecycle soak проверяет и журнал, а не только выживание процесса и исчезновение окна.
- UI-тесты настроек сами создают приватную D-Bus-шину без activation directories, HOME/XDG и аудио-изоляцию. Не полагаться на Fcitx/порталы рабочего пользователя: нужные методы задаёт fixture. Для QML runtime копировать и плагины, и shared dependencies (RUNPATH может вести в build); /proc/PID/maps проверяется run_snapshot_qml.
- Для продолжительных интерактивных VM-soak нужны временный inhibit и нейтральная виртуальная активность; IPC-открытие страниц не является гарантированным пользовательским вводом. Не считать окна за lock screen доказательством видимого UI. Отдельные power-тесты не используют такое удержание.
- Стенд virtio-vga на проверенной CachyOS зависал в ядре после S3 (virtio_gpu queue); VGA/bochs-drm прошёл suspend/resume. Выбирать GPU явно и сохранять hardware scope измерений. QMP suspended — не завершение процесса; сначала wakeup/диагностика, а не новый запуск.
- Частный главный Lua-файл не обеспечивает атомарность пакетных require-модулей. При upgrade проверять emergency banner/keybinds, а не только configerrors. Не перезапускать владельца session lock ради обновления без согласованного безопасного перехода.

### Уроки пакетного обновления и session lock

- Arch hook не останавливает работающие пользовательские службы: идемпотентный
  start сохраняет владельца session lock, configuration guard и фоновые задания.
  Проверка lock.isLocked перед внешним restart недостаточна из-за TOCTOU.
  Изменение кода работающих служб применяется при новом входе до появления
  проверенного согласованного механизма перезапуска.
- При pacman upgrade автоматический file watcher Hyprland временно защищается
  hics-package-config-guard: READY после отключения, cleanup через ExecStopPost,
  сохранение исходного пользовательского disable_autoreload. В Lua parser
  использовать hl.config через eval, а не legacy keyword. Тестировать также
  SIGKILL guard, возврат наблюдения реальным изменением и сохранность bindings.
  Не считать это защитой от явного reload или доказательством целостности
  пакета, распаковка которого была аварийно прервана.


- Подключение QMediaDevices::audioInputsChanged запускает Qt Multimedia backend
  через connectNotify. Не подписываться в конструкторе общей network/storage
  интеграции: создавать наблюдателя только на время проверки микрофона и
  освобождать при stop. Проверять /proc/self/maps и ASan/LSan; аллокации драйвера
  при выходе не выдавать за доказанный длительный рост RAM.
- Внешние команды ограничиваются не только timeout: дренировать stdout/stderr
  по мере чтения с отдельными бюджетами, не передавать многомегабайтный stderr
  в UI. Overflow, FailedToStart и timeout завершают запрос ровно один раз;
  в журнале — компонент/категория, без argv/сырого вывода. Qt может писать
  предупреждения напрямую в journal; для проверки stderr использовать
  QT_FORCE_STDERR_LOGGING в fixture, не менять ради теста рабочую сессию.


- Qt Quick Controls popup не обязан наследовать attached Config/Tokens из
  визуального родителя. Для меню/ToolTip явно передавать screen самому popup,
  contentItem и background. Проверять реальные отличающиеся настройки монитора,
  а не только отсутствие предупреждений при глобальном масштабе 1.
- Привязки Window/Popup читаются до заполнения screen. Диагностику отсутствующего
  контекста откладывать до завершения текущей сборки QML, с QObject lifetime и
  дедупликацией; намеренно непривязанный объект должен по-прежнему предупреждать.
- Отсутствующий ~/.face — штатный fallback, не ошибка декодера. Один observer
  на QML engine; следить за каталогом и переустанавливать file watch после
  atomic replace. Не декодировать FIFO/директории. Обновление проверять по
  пикселям при сохранённых size/mtime: одного нового URL недостаточно, если
  устаревший disk cache возвращает прежнюю картинку. Не запускать decode при
  нулевой геометрии; sourceSize учитывает DPR. Не маскировать реальные ошибки
  прочих изображений ради отсутствующего аватара.

## Дополнение: повторные запуски и проверка восстановления

- Динамические биндинги должны быть идемпотентны между процессами shell и повторно устанавливаться после config reload. Lua guard принадлежит Lua-состоянию композитора. Не удалять все биндинги по клавише и не воспроизводить opaque __lua IDs.
- При legacy read/commit очередь занята до подтверждения записи; ответ старого поколения не разрешает новую запись.
- В проверках main shell определять через прямого ребёнка session runner. pgrep может включать IPC/PAM помощников и сам по себе не доказывает два UI.
- Стресс-перезапуски учитывают systemd StartLimit. Не ослаблять защиту ради теста; явный штатный recovery resume может сбрасывать счётчик только своего сервиса. Никогда не перезапускать владельца заблокированной сессии ради обхода авторизации.
