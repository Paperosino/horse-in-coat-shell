# Исправления частного Qt runtime hics

Пакет109 включает три локальных исправления **Qt6.12.0**. Кандидат110
добавляет исправление владения материалом RectangularShadow; его установка
ожидает полной приёмки. Системный Qt и
библиотеки других приложений не заменяются. При переходе на другую версию Qt
нужны повторный разбор исходников, перенос патчей и приёмка; сборка пакета
останавливается при несовпадении версии/проверяемых feature flags.

## Регистрация порталов

Исходная регистрация помечалась завершённой только после асинхронного ответа.
Несколько экземпляров QDesktopUnixServices успевали отправить несколько
Register на одно соединение. После перезапуска portal первоначальный static
флаг, наоборот, не позволял зарегистрироваться заново.

Владелец регистрации теперь живёт с приложением, учитывает pending-запрос,
поколение владельца D-Bus и его смену. Поздний ответ старого сервиса не меняет
состояние нового. Ошибки действительного отказа сохраняются в журнале.

Это следует требованиям [Registry](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.host.portal.Registry.html):
однократная регистрация до использования portal API, повторная регистрация
после смены владельца. Чтение capability Properties.Get в проверенной версии
frontend не создаёт app association: отдельная проверка с настоящим frontend
успешно зарегистрировала приложение после этого чтения. Произвольные вызовы
порталов до регистрации безопасными от этого не становятся.

## Wayland text input

При переходе из поля ввода в другое окно без поля Qt пытался отключить новую
поверхность вместо ранее включённой. Исправление отключает предыдущую
поверхность и включает новую только при принятом методом ввода объекте.
Изменение не подменяет фокус Hyprland и не фильтрует предупреждения.

## Multimedia

Конструктор FFmpeg integration перечислял аппаратные кодеки исключительно
для debug-сообщения, даже при выключенной debug-категории. Простое перечисление
аудиоустройств поэтому загружало CUDA/VDPAU и оставляло обнаруженные LSan
выделения. Обход для диагностики выполняется только при включённой категории;
реальный выбор аппаратного видеодекодера остаётся прежним.

Это исправление проверенного audio-only пути, **не утверждение об отсутствии
всех утечек multimedia или GPU-драйверов**. Переменные, отключающие аппаратные
кодеки, в production не добавлены. Подавления LSan не используются.

## Тени RectangularShadow

В [исходнике Qt6.12.0](https://github.com/qt/qtdeclarative/blob/v6.12.0/src/effects/qquickrectangularshadow.cpp)
private-конструктор создаёт default material до того, как QObject установит
q_ptr. Переданный Q_Q поэтому ещё не задаёт владельца. Визуальный parent
появляется позже, но он не заменяет QObject-владение, и шейдер переживает тень.
Патч явно создаёт материал без преждевременного Q_Q и назначает QObject-parent
из public-конструктора. Пользовательский материал не присваивается во владение
тени, его API и переключение к default material сохраняются.

Пересобирается только QuickEffects из закреплённого qtdeclarative, против
совпадающих private Qt Qml/Quick headers; исходные Qml/Quick и declarative
plugins остаются в bundle. У100 реальных объектов исходный runtime оставлял
материалы в памяти, исправленный проходит ASan/LSan. Шесть render cases в ВМ
с разными blur/radius/spread/color/cache дают попиксельно одинаковые PNG до
и после. Это не заменяет приёмку всей оболочки или физических GPU.

## Жизненный цикл Quickshell

Частный Quickshell0.3.2 также содержит закреплённые source patches: владение
именами категорий в очереди/кэшах журнала, порядок завершения QML/application
и владение процессами при удалении QML Process. Асинхронное завершение не
оставляет QObject без владельца перед остановкой event loop. Только финальный
выход приложения допускает ограниченное ожидание reap; обычный QML teardown
не ждёт процессы. Manifest связывает executable SHA с полным набором патчей.

## Воспроизводимая сборка и доставка

`distribution/build_qt_runtime_patches.py` загружает исходники по закреплённым
SHA256, применяет patch с fuzz=0, проверяет feature flags и создаёт неизменяемый
overlay. QtCore/DBus/Gui/WaylandClient/QuickEffects и три выбранных plugin пересобираются;
исходные QtMultimedia/Quick/Qml и остальные плагины сохраняются. Vendored md4c
сохраняет поддержку Markdown при несовместимости актуальных системных headers.

CMake включает этот шаг перед сборкой частного QS. RPATH относительный,
без путей к рабочей машине. Manifest хранит исходники, патчи, параметры и
контрольные суммы файлов/aliases. `apply_qt_runtime_patches.py` проверяет их
перед публикацией и заменяет файлы атомарно: открытый inode работающего
процесса не перезаписывается. PKGBUILD повторно проверяет установленный manifest.
`HICS_PATCH_QT_RUNTIME=OFF` допустим для отдельной разработки; такая сборка
не должна выдаваться за содержащую эти исправления.

## Приёмка

- `diagnose_qt_portal_registration.py`: активный/активируемый mock, перезапуск
  после ответа и во время pending, настоящий отказ политики; три экземпляра Qt.
- `integration_qt_portal_frontend.py`: настоящий xdg-desktop-portal, private bus,
  отдельный desktop fixture, без перезапуска пользовательского portal.
- `integration_qt_text_input.py`: nested Hyprland, private Fcitx5, переключение
  полей, Compose, создание и уничтожение шести окон с активным вводом; также
  отдельный прогон без IME. Это не проверка каждого существующего метода ввода.
- `diagnose_qt_multimedia.py`: 200 перечислений аудиоустройств, фактически
  загруженный FFmpeg backend, ASan/LSan без suppressions и без HW-disable env.
- `test_wallpaper_playback.py`: цветные кадры, pause/resume, restart и потеря
  sink после первого реального кадра. Проверка watchdog не должна отключать
  sink по произвольной задержке до готовности декодера на холодном старте.
- `diagnose_qt_shadow_lifetime.py`: default/custom material,100 объектов, ASan/LSan.
- `qt-shadow-render.qml` с VM profiler: попиксельное сравнение шести теней.
- `diagnose_quickshell_process_lifetime.py`: выход с тремя запущенными процессами.
- `test_qt_runtime_overlay.py`: checksums, aliases, обход путей, symlink/FIFO
  manifest, сохранение старого inode и остальных plugins.

Software VM подтверждает эти сценарии, но не производительность физических
GPU, аппаратный decode всех форматов и отсутствие роста RAM при многодневной
работе. Эти проверки остаются отдельными воротами общей кампании.

Частный QS с upstream USE_JEMALLOC использует процессную стартовую политику
из `distribution/quickshell_allocator/policy.cpp`. Инициализированная константа
читается до main, без таймеров очистки, позднего mallopt и экспорта MALLOC_CONF
в приложения. Диагностическая сборка USE_JEMALLOC=OFF остаётся возможной.
Пакет проверяет наличие политики в ELF и контрольные суммы runtime; нативная
проверка читает реальные mallctl значения и проверяет приоритет пользовательской
настройки. Изменение аллокатора не заменяет ASan/LSan и проверку визуала.
