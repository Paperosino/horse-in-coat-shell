# Кампания устойчивости HICS

Цель — полная проверка установки и функций на CachyOS, провокация отказов,
исправление находок, анализ ресурсов и понятная диагностика. Этот документ —
журнал доказательств и оставшейся работы, а не заявление «всё проверено».

## Испытательное окружение

- QEMU/KVM, 2 vCPU, 4096 MiB RAM, виртуальный диск 60 GiB (qcow2, thin).
- Нет проброса физических дисков, общих каталогов или изменения сети хоста.
  Сеть user-mode; SSH опубликован только на 127.0.0.1:22280.
- QMP и serial — Unix-сокеты в приватном каталоге лаборатории.
- Официальный ISO CachyOS Desktop 260809. SHA256:
  `959f6577f45e25ee9fd8c220fd221b08e4ea79412c7315c0f922dd6d86d5e33c`.
  Проверена подпись ключом `882DCFE48E2051D48E2562ABF3B607488DB35A47`
  из установленного cachyos-keyring. Его armored public-key file сначала
  преобразован через gpg --dearmor, затем выполнен gpgv.
- Источники: [ISO и проверка](https://wiki.cachyos.org/cachyos_basic/download/),
  [зеркало ISO](https://build.cachyos.org/ISO/desktop/260809/),
  [systemd debug console](https://www.freedesktop.org/software/systemd/man/latest/systemd-debug-generator.html).
- Базовая ОС установлена guarded pacstrap из официального live-окружения.
  Это не тест Calamares. Подтверждены ID=cachyos, ядро linux-cachyos 7.2.7-1,
  CachyOS settings, UEFI/GRUB, Btrfs @/@home и загрузка с диска без ISO.
  На базовом старте systemctl --failed не содержит юнитов.
- Базовый диск сохранён отдельно; эксперименты идут в overlay. Root-доступ
  лаборатории — по отдельному SSH-ключу. Ключи, диски, пароли и сырые логи
  не добавляются в Git. Debug-shell включается только для установочного
  live ISO; установленная ОС запускается без него.

## Воспроизведение

Скрипты находятся в tests/:

- `run_stability.py --out PRIVATE_DIRECTORY` — каждый test_*.py отдельно,
  с приватными HOME/XDG, недоступными настоящими D-Bus-шинами, offscreen Qt,
  таймаутом и отдельным логом. Manifest содержит исходную ревизию, dirty-state,
  результаты, пропуски и SHA256 изменённых исходников. Первый baseline был
  снят до добавления fingerprint-списка; это ограничение его доказательств.
- `vm_cachyos.py start --lab PRIVATE_DIRECTORY` — boot официального ISO.
  ISO, SHA256, извлечённые kernel/initrd должны находиться в каталоге lab.
- `vm_cachyos.py start --installed --lab PRIVATE_DIRECTORY` — boot диска;
  `status` использует настоящий QMP, `stop` посылает QMP quit.
- `vm_bootstrap_cachyos.sh --disposable-cachyos-vm` выполняется **внутри ВМ**.
  Guard проверяет QEMU, live ISO, пустой writable vda размером ровно 60 GiB.
  Повторный запуск на размеченном диске запрещён. Установленные настройки
  рассчитаны на тестовый стенд, не на развёртывание пользовательского ПК.

Перед snapshot/reset остановить гостевую ОС, проверить освобождение qcow2 и
не перезапускать ВМ только из-за истечения времени наблюдения. Её живость
подтверждается QMP и состоянием процесса. Команды разрушения ОС, OOM, обрывов
установки и kernel panic разрешены исключительно в disposable guest.

## Результаты первого базового прогона

63 модуля, 313 тестов, 5 пропусков, два упавших модуля. Логи сохраняются
раздельно; baseline не переписывается последующими зелёными результатами.
Пропуски: два теста application scopes требуют user systemd, один broker
runtime требует user systemd, два network QML требуют Wayland. Они остаются
незакрытыми до отдельного подходящего прогона.

После baseline выполнены отдельные прогоны с нужными условиями:
application scopes — 2/2 на реальном user systemd (только временные fixture
units); broker runtime — 8/8, включая зависание и рестарт только его временного
юнита; network QML — 2/2 с Wayland и приватным NetworkManager fixture.
Пропусков в этих трёх прогонах нет. Это закрывает перечисленные предпосылки
тестов на хосте, но не заменяет повтор в гостевом графическом сеансе.

| ID | Контекст и доказательство | Исправление / состояние |
|---|---|---|
| STAB-001 | DesktopIntegration: без session D-Bus busy=true после завершения всех процессов и вызовов. Диагностика показала pendingCalls=0, pendingProcesses=[] | Watcher обрабатывает уже завершённый QDBusPendingCall, подавляет повторное завершение, учитывает lifetime через QPointer. 13 тестов проходят, включая положительный ответ ScreenCast portal, отсутствующую session-шину и обе отсутствующие шины |
| TEST-001 | Экспорт сессии: при umask 077 mkdir(mode=0750) создавал 0700 ещё до вызова экспорта | Fixture явно задаёт исходные 0750; проверка сохранения прав не ослаблена. 26 тестов проходят в изолированном окружении |
| LAB-001 | Modular QEMU не содержал virtio-vga | Установлены модули virtio GPU/VGA и EGL; не включались libvirt services и не менялся firewall хоста |
| LAB-002 | CachyOS initramfs не увидел виртуальный IDE CD-ROM | Установочный ISO подключён readonly virtio-блоком; успешный live boot подтверждён |
| LAB-003 | Headless live boot ожидал firstboot/time-wait до сети | Только в live boot маскируются эти два юнита. В установленной ОС заданы locale, hostname, timezone; debug console не используется |
| LAB-004 | FAT volume label превышал 11 символов | Исправлен на HICS_ESP; исходная неудачная разметка была пустой и проверена до её сброса. Повторная установка ОС завершена |
| INSTALL-001 | На чистой системе resolver выбрал chipass для seahorse до обработки явно требуемого gnome-keyring. Установлены оба | gnome-keyring перемещён в начало обязательных depends. План кандидата 1.1.1-80 с пустой локальной pacman DB подтверждает gnome-keyring+seahorse без chipass. Реальная повторная установка на чистом snapshot ещё требуется; лишние провайдеры существующего пользователя автоматически не удаляются |

## Первая установка пакета

Кандидат hic-shell 1.1.1-79 установлен публичным install.sh --package от обычного
hics-test пользователя без GUI и без его user bus. Для автоматического стенда
выдано guest-only sudo-разрешение на pacman; это не настройка хоста/продукта.

Проверено: dry-run, разрешение/загрузка зависимостей, установка, включение
hics-system/hics-memory и четырёх пользовательских юнитов, активность двух
системных служб, отсутствие failed units. Это **не** доказательство рабочего
графического сеанса: GUI/логин/каждая функция ещё требуют испытаний.

## Обязательная матрица дальнейших проверок

| Область | Что должно быть подтверждено |
|---|---|
| Установка | Повторный fresh install после INSTALL-001; установка из исходников; обновление/переустановка/удаление; offline/chroot/TTY; отказ mirror и полное место |
| Сеанс и аварии | Реальный login/logout, cold startup, crash loop, safe mode, last-good, rollback, отказ IPC, поведение при lock screen; приложения переживают рестарт |
| Все страницы/виджеты | Реальное действие каждой настройки, клавиатура/мышь, внешние клики, Escape, узкие экраны, DPR, локали, high contrast/reduced motion, живые обновления |
| Окна | Все четыре режима; Wayland/X11/GTK/Qt; CSD/SSD; fullscreen/maximize; фокус, док, превью, уведомления и геометрия |
| Системные функции | Сеть/VPN/portal, звук, диски/шифрование, питание/память, печать, устройства, пользователи, firmware, backup, permissions — success/error/cancel/unavailable |
| Протоколы | D-Bus разрывы/смена owner/late reply; portal lifecycle/permissions; IPC malformed/oversize; Wayland destroy/reuse/grab/lock |
| Ресурсы | CPU/RSS/PSS/VRAM и таймеры в idle и нагрузке; длительные циклы открытия/закрытия; sanitizers/утечки; отсутствие постоянного polling без потребителя |
| Диагностика | Контекст ошибки, конкретное следующее действие, журнал с redaction паролей/токенов, лимит размера/срока хранения, retry без фиктивного успеха |
| Брендинг | Новый SVG HICS и нативный Logo; исходный маскот сохранён. Все GIF/видео/тур и документационные изображения нуждаются в визуальном аудите и реальных перезаписях при наличии старого бренда |

Новые watchdog/stabilizer services добавляются только при доказанной
необходимости: сначала устраняется причина сбоя. Один замер большого RSS не
считается утечкой. VM, mocks и nested compositor не доказывают работу всех
физических устройств, GPU/VRR и сторонних VPN серверов; границы каждого
результата должны быть указаны явно.

Повторный изолированный прогон после исправлений: 63 модуля, 315 тестов,
без падений, с теми же пятью явно учтёнными пропусками. Дополнительный
положительный portal-case проверен отдельным набором из 13 тестов.

В госте также проверено обновление публичным installer 1.1.1-79 → 1.1.1-80:
успешный exit, обе системные службы active, failed units отсутствуют.
На рабочем хосте остаётся ранее установленная 1.1.1-78. Графическая сессия
ВМ ещё не испытана. Полная кампания не завершена.
