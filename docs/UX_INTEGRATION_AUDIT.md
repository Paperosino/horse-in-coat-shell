# Запуск, интеграции и движение интерфейса

## Методика запуска

Измерять отдельно подготовку runner, загрузку QML и первый отправленный видимый
кадр. `Configuration Loaded` не означает появление готового рабочего стола.
Новый `StartupPerformance` подключается к `frameSwapped` видимых QQuickWindow,
публикует один сигнал и снимает наблюдение. Это факт передачи кадра, не измерение
задержки физической матрицы монитора.

Погода, дополнения удобства, обнаружение зависших приложений, captive portal,
фоновое наблюдение интеграций и загрузка defaults начинают необязательную
инициализацию после этого сигнала. Они остаются доступны раньше по прямому
обращению. Уведомления, раскладка окон, обои, защита конфигурации/экранов,
игровая политика и idle inhibition не откладываются. Автоочистка миниатюр также
не запускает дисковую работу до первого кадра. Шейдеры, анимации и частота экрана
не упрощаются.

Подсказка горячих клавиш также загружается по URL при первом открытии, без подключения каталога страниц к корневому компоненту.

Тур загружается через небольшой `TourContent.qml`, который сам импортирует его
каталог. Это откладывает граф зависимостей тура и сохраняет обнаружение DemoCard
при загрузке по URL. Первое открытие тура проверяется отдельно от старта.

Для теста без прогретого QML-кэша:

```bash
python3 tests/benchmark_startup.py --fresh-cache --evict-source --check-ui
```

Каждый проход получает новый каталог кэша. `--evict-source` вызывает fsync и
POSIX_FADV_DONTNEED только для собственных временных копий ресурсов. Библиотеки,
драйвер, кэш дискового контроллера и ядро могут оставаться прогретыми. Это
контролируемый стресс-тест старта, **не эквивалент перезагрузки компьютера**.
`--probe-frame --source /путь/к/предыдущему/shell` добавляет такое же наблюдение
первого кадра к предыдущей версии для сравнения. Ни drop_caches, ни перезапуск
пользовательского композитора не требуются.

Контрольный замер на текущей машине с новым кэшем в каждом проходе: предыдущая
версия отправила первый кадр за 3,009 / 2,845 / 2,741 с; новая — за
2,945 / 2,781 / 2,740 с. Разница мала относительно разброса: заметное ускорение
настоящего холодного входа **пока не подтверждено**. Барьер первого кадра
устраняет раннюю необязательную работу, но не отменяет стоимость Qt/QML и
инициализации графического стека. Перезагрузка пользовательского сеанса ради
измерения не выполнялась.

## Счётчики приложений

`ApplicationBadges` слушает session D-Bus LauncherEntry.Update, обрабатывает
частичные обновления count/count-visible и объявляет com.canonical.Unity, если
имя свободно. Чужой владелец не заменяется. Состояние ограничено по размеру,
привязано к уникальному отправителю и удаляется при его отключении. Асинхронная
проверка владельца закрывает гонку с очень короткоживущим отправителем.

Док использует desktop id из каталога приложений; количество показано в одном
значке на группу окон. Источники выбираются в настройках дока:

- данные приложения с резервным счётом истории;
- только интеграция приложения;
- только непрочитанные уведомления оболочки.

Значение приложения имеет приоритет и не суммируется с историей. count-visible
false скрывает его до следующего обновления или отключения отправителя.
Отсутствие интеграции не позволяет оболочке узнать реальное число непрочитанных
диалогов: резервный счёт относится только к истории hics. Заголовки окон не
разбираются и приватные базы мессенджеров не читаются. Числа выше 99 показаны как
99+. Значок движется с иконкой, не создаёт собственного обработчика мыши,
поддерживает reduced motion и скрывается на экране презентации с приватностью.

## Системные порталы

В разделе демонстрации экрана появился обзор экспортируемых интерфейсов:
выбор файлов, открытие ссылок, ScreenCast, RemoteDesktop, Screenshot, Settings,
камера, Background, Notification, Secret, печать, GlobalShortcuts,
DynamicLauncher и Inhibit. Наличие интерфейса не обещает успешность каждого
запроса: важны бэкенд, версия и оборудование. Оболочка не подменяет штатный
экран выбора источника захвата.

В свойствах приложения доступны разрешения PermissionStore для камеры,
фоновой работы и уведомлений. Можно разрешить, запретить или вернуть политику
портала. Сброс уведомлений обычно означает разрешение, а не обязательный запрос.
Применяются только известные таблицы; произвольная таблица из UI не принимается.
Прямой доступ обычного приложения и уже открытая сессия захвата не отзываются
этими переключателями. Разрешение портала и Flatpak overrides — разные уровни.

Семантика сверена с первичными описаниями:
[PermissionStore](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.impl.portal.PermissionStore.html)
и [таблицы разрешений](https://github.com/flatpak/xdg-desktop-portal/wiki/The-Permission-Store).
Совместимость LauncherEntry сверена с
[реализацией Dash to Dock](https://github.com/micheleg/dash-to-dock/blob/master/launcherAPI.js).

## AppArmor

В свойствах приложения профиль выбирается из установленного списка, без ввода
пути. Доступны режимы enforce/complain/disable и визуальные дополнительные
запреты IPv4/IPv6, прямого доступа к камере/звуку, домашним и смонтированным папкам.
Они записываются в управляемый блок стандартного local-include профиля.
Посторонние локальные правила сохраняются. Снятие дополнительного запрета
наследует исходный профиль, а не выдаёт новое разрешение.

Для профилей без стандартного local-include GUI не угадывает синтаксис и не
вставляет текст по последней фигурной скобке. Режимы и расширенный редактор
остаются доступны. Сохранение запретов не выдаётся за загрузку в ядро: после
сохранения интерфейс явно предлагает Enforce. При complain это также переводит
профиль в режим защиты. Устройства, открытые через PipeWire/порталы, имеют
отдельную политику; запрет /dev/video не является универсальным выключателем
камеры.

Запись требует polkit, проверяет владельца и symlink, размеры, исходные SHA-256
обоих файлов, валидирует генерируемый фрагмент штатным apparmor_parser,
сохраняет резервную копию изменяемого локального содержимого и пишет атомарно.
Основной профиль не переписывается визуальными контролами. Тесты работают в
mount/user namespace и не изменяют реальные профили.

## Правила и панель

Выбор открытого окна автоматически заполняет класс и протокол X11/Wayland.
Выбор приложения устанавливает протокол только когда все его открытые окна
одного протокола; иначе правило охватывает оба. Настройка области совпадения
(приложение, заголовок, начальный заголовок) остаётся явной. Идентификатор,
позиция, режим и эффекты редактируемого правила сохраняются. Ручные поля и
переопределения перенесены в расширенное сопоставление.

Панели → «Высота панели и виджеты» содержит автоматическую высоту/масштаб и
отдельную высоту 24–112 логических пикселей. Значки, текст и интервалы следуют
этой высоте, исключая обрезку. Попасть туда можно также через ПКМ по панели.
Work area, input region и отступы сетки рабочего стола используют фактический
размер BarWrapper.

## Аудит анимаций

`python3 distribution/audit_motion.py` инвентаризирует все QML-файлы. При этом
проходе просмотрено 470 файлов, в 162 явно встречались механизмы анимации;
остальные часто наследуют общие контролы. Фиксированный duration — кандидат
для проверки, а не автоматически ошибка. Нельзя анимировать каждое значение
датчика или включать постоянный render loop для имитации плавности.

Исправлены общие места:

| Место | Исправление |
| --- | --- |
| Настройки панели/рабочего стола по ПКМ | Появление через токены FastSpatial, закрытие без задержки ввода |
| Общие выпадающие меню | Токен FastSpatial вместо отдельной кривой 90 мс |
| Ошибки настроек | Плавное появление и схлопывание с сохранением текста на время ухода |
| Всплывашки панели | Общий пространственный переход; reduced motion действует и на смещение по X |
| Приглушение иконок дока/задач | Токен FastEffects |
| LoadingIndicator | В reduced motion останавливаются вращение и изменение формы |
| Волны CircularProgress и обложка плеера | Декоративные бесконечные движения при reduced motion остановлены |
| Логотип в «О системе» | Общие токены эффектов/пространства |
| Индикатор таймера подтверждения экрана/профиля | Общий FastEffects; сам защитный таймер не меняется |
| Переход стакинга | Учитывает reduced motion без изменения длительности обычного режима |

Остающиеся специальные тайминги дока (импульс поглощения), ввода пароля и
клавиатурного предпросмотра требуют проверки по их сценарию; одинаковая замена
всех интервалов одним easing испортит согласование. Инвентаризация не является
доказательством отсутствия всех визуальных дефектов на любом оборудовании.

## Чёткость при масштабировании

Проверка панели выявила NativeRendering в общем StyledText: трансформация панели
масштабировала готовый растр текста. StyledText и поля ввода переведены на
сглаженный QtRendering; Material Symbols и цифры счётчика используют повышенное
качество distance field. Общий текст сохраняет штатное качество, чтобы не
увеличивать размер атласа для всех абзацев. Это согласуется с
[описанием Qt](https://doc.qt.io/qt-6/qml-qtquick-text.html#renderType-prop).

FontBuilder и FontStyle теперь сохраняют qreal/pointSizeF. ScalableIcon задаёт
стабильный sourceSize под предел трансформации, а не под текущую волну, включает
mipmap и гладкую фильтрацию. Recolour-layer получает соответствующий физический
textureSize с DPR. Панель передаёт свой масштаб потомкам; док задаёт верхнюю
границу hover/импульса. Плашка и шрифт счётчика пропорциональны размеру иконки.

Регрессии: UI scale 0,75 / 1 / 1,25 / 1,5 / 2; Qt DPR 1,25 и 2; док 32/44/64;
настоящее изображение превью, промежуточные состояния раскрытия, переключение
окон, закрытие меню и клики по четырём сторонам дока. Исходный низкокачественный
растровый значок невозможно превратить в вектор; для него доступно корректное
семплирование исходника.
