# Оформление окон hics

## Единая политика

`native/hyprbars/decoration-policy.cpp` — единственный источник решения о серверном заголовке. Политика не читает имя приложения, класс окна, пиксели, геометрию теней, непрозрачные области или историю запросов перемещения. Заголовок, контур фокуса и доступность оконных действий независимы.

Порядок выбора:

1. Неуправляемые X11-поверхности, popup-роли и явно отключённое оформление не получают заголовок.
2. Эффективное ручное правило `titlebar: show/hide` (нативный эффект `hyprbars:no_bar`) переопределяет автоматический выбор у управляемого окна. `decorate: false` по-прежнему отключает и остальные декорации.
3. Для Wayland действует согласованный `xdg-decoration`, затем устаревший KDE server-decoration. Явная просьба клиента использовать CSD теперь учитывается; предпочтение по умолчанию для участвующих в переговорах клиентов — SSD.
4. Без переговоров Wayland-клиент отвечает за своё оформление. Это не утверждение о том, нарисовал ли он собственный заголовок: намеренно безрамочное окно тоже допустимо.
5. Для X11 используется `_MOTIF_WM_HINTS`: учитываются флаг DECORATIONS, бит TITLE и исключающая семантика ALL. Отсутствующие, некорректные и не относящиеся к оформлению свойства означают обычный серверный заголовок.

`_NET_FRAME_EXTENTS` устанавливается оконным менеджером и не используется как запрос клиента. `window_geometry` применяется только для корректной отрисовки и координат ввода. Родительские отношения и модальность не означают отсутствие заголовка.

Ручное «Показывать» не удаляет произвольный HeaderBar или DOM приложения: если клиент продолжает рисовать собственную шапку, возможен двойной заголовок. «Автоматически» следует протоколу. Выбор сохраняется в существующем редакторе правил с поддержкой режимов окон.

## Состояния и жизненный цикл

Новый режим xdg-decoration вступает в силу после соответствующего `ack_configure` и следующего коммита поверхности. Удаление объекта декорации действует на следующем коммите. Реестры привязаны к времени жизни ресурсов Wayland; повторное использование адресов окон не переносит старую политику.

В Hyprland 0.56.2 используются перехваты конструкторов объектов протокола и публичных методов сгенерированных обёрток. Простые приватные функции выбора режима встроены компилятором и не являются надёжной точкой перехвата. Макрос `private public` для политики не применяется. Исходные обработчики сохраняются и восстанавливаются при завершении плагина; его лямбды не должны переживать выгрузку библиотеки.

Начальное Motif-свойство запрашивается асинхронно через libxcb. Дальнейшие изменения используют ответ, который уже прочитал XWM. Нет внешнего процесса, таймера опроса или синхронного ожидания ответа на запрос свойства в потоке композитора. Версия свойства защищает от замены свежего изменения запоздалым начальным ответом. Запросы отменяются при закрытии окна.

Заголовки CSD/SSD не влияют на обработку нативных `move/resize`, maximize, minimize и close. Геометрия стакинга получает реальную высоту серверного заголовка из C++, а не повторяет классификацию в Lua. Плиточное окно больше не объявляется maximized исключительно ради подавления CSD.

При обновлении пакет не перезагружает нативный плагин в работающем композиторе. Для новой политики нужно выйти из графического сеанса и войти снова. Подключение к существующим переговорам через горячую переустановку плагина не поддерживается.

## Диагностика

Lua API `hl.plugin.hyprbars.decoration_policy(address, stable_id)` возвращает JSON с `mode`, `source`, `titlebar` и `height`. Проверяются и адрес, и стабильный идентификатор окна. `hl.plugin.hyprbars.decoration_stats()` показывает размеры реестров и число ожидаемых X11-запросов; тест проверяет их полное освобождение после закрытия клиентов. Возможные источники: `xdg-decoration`, `kde-decoration`, `wayland-self-decoration`, `motif-hints`, `x11-default`, `user-show`, `user-hide`, `decoration-rule` и роли поверхностей.

Назначение окон (например, Telegram Media Viewer или Picture-in-Picture), их размещение и активирование — отдельная политика. Существующие узкие правила такого поведения не являются детекторами CSD и сохранены.

## Проверки

- `tests/integration_decoration_policy.py`: настоящий клиент xdg-decoration, смена режима, отложенное подтверждение, уничтожение объекта, геометрия, ручные переопределения, GTK4, Qt Widgets и Motif/X11.
- `tests/integration_window_decorations.py`: один и тот же SSD-клиент с разными app ID, области отрисовки заголовков, правила по режимам и PiP.
- `tests/integration_stacking_drag.py`: реальные движения мыши, восстановление развёрнутого окна, нативные GTK4/X11 maximize/minimize, X11 resize/cancel.
- Регрессии ввода холста проверяют отдельно GTK и Qt.

## Фокус X11 после интерфейса оболочки

`keyboard-focus.hpp` синхронизирует фокус seat и активацию XWM при переходах между приложением и layer-shell интерфейсом. Освободившийся seat восстанавливается после завершения текущего перехода; запасная проверка перед нажатием клавиши исправляет рассинхронизацию с кэшированным desktop focus. Интерактивные слои, другие приложения, захваты и экран блокировки сохраняют владение клавиатурой. Холст использует `rawSurfaceFocus`, а не отдельную запись в seat.

Регрессия запускается во вложенном композиторе: реальные X11 key events после скрытия слоя и отключения его keyboard interactivity, управляемая инъекция рассинхронизации seat, обычная и `WM_TAKE_FOCUS` модели клиента. Тестовый плагин инъекции не устанавливается в пакет.
