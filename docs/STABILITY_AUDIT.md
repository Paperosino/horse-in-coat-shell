# Аудит стабильности hics

> Исторический этап аудита. Текущая расширенная кампания, границы покрытия
> и новые находки: [RELIABILITY_CAMPAIGN.md](RELIABILITY_CAMPAIGN.md).


Дата: 24 октября 2026. Среда: Arch Linux, Hyprland 0.56.2, NVIDIA RTX 3080,
DP-3 1920×1080, 164,998 Гц. Пакет с исправлениями: `hic-shell 1.1.1-30`.

## Исправления

| Область | Проблема | Изменение |
| --- | --- | --- |
| Вызовы вспомогательных сервисов | Между остановкой процесса и обработкой его ответа мог начаться следующий запрос | Запрос остаётся занят до завершения обработчика; ответы привязаны к исходному запросу |
| Ошибки процессов | Ненулевой код с пустым ответом мог выглядеть успешным для вызывающего кода; неудачный запуск мог остановить очередь | Ошибка передаётся в callback; отложенный обработчик восстанавливает очередь при FailedToStart |
| Настройки системы | Сброс мог проиграть ещё не отправленному изменению ползунка | При сбросе удаляется отложенная запись соответствующего параметра |
| Системная интеграция | Каждые пять секунд запускались `hyprctl clients`, `hyprctl monitors`, `pactl`, `pw-dump` и запросы Wi-Fi | Фоновый монитор запрашивает только накопители и потоки захвата; полный набор обновляется при обращении страниц настроек |
| D-Bus портала | Запрос возможностей трансляции не входил в счётчик занятости | Запрос учитывается до получения ответа; повторные обновления не перекрывают его |
| Индикация захвата | При исчезновении или неудачном запуске `pw-dump` сохранялся устаревший список потоков | Недоступность мониторинга очищает старое состояние |
| Восстановление сессий | Периодическое чтение всех снимков и лишние сигналы обновления | Наблюдение за файлами и каталогами, объединение событий за 100 мс, уведомление только при изменениях |
| Чтение снимков | Ошибка одного файла могла оставить частично перестроенный список | Новый список публикуется целиком после успешного чтения; предыдущий сохраняется при ошибке |
| Файловые события | Атомарная замена файла удаляет наблюдение за старым inode | Наблюдение за каталогами и повторная установка наблюдения за файлами; отложенное чтение во время операций записи |
| Диагностика установки | `hics-doctor` проверял пользовательский каталог вместо системного пакета | Выбранный каталог установки экспортируется всем вспомогательным процессам |
| Подписки виджетов | Первый запуск сервиса мог синхронно создать второго подписчика и повторно вызвать запуск | Подписка регистрируется до вызова `start()`; проверены повторная подписка и уничтожение подписчиков |
| Батарея | Отсчёт до гибернации продолжался после подключения зарядки или восстановления заряда | Отсчёт отменяется; непосредственно перед гибернацией состояние проверяется повторно |
| Hyprland IPC | Чтение старого формата `descriptions` давало пустые параметры на 0.56 | Поддерживаются оба формата; отсутствующие ключи не публикуются |
| Текущие параметры Lua | `descriptions.current` содержит значения по умолчанию, а не рабочие значения Lua | Нужные параметры дополнительно читаются одним пакетным запросом `getoption` |
| Игровой режим | Отключённые анимации ошибочно считались игровым режимом | Независимый явно переключаемый флаг |
| Владение параметрами | Игровой режим и Effects одновременно меняли тени при reload | Управление тенями оставлено Effects; игровой режим сохраняет только принадлежащие ему параметры |
| Выход из игрового режима | Полный reload затрагивал весь рабочий сеанс | Сохраняются и восстанавливаются только изменяемые параметры; reload внутри игрового режима обновляет исходный снимок после завершения чтения конфигурации |
| Lua-параметры | Строки передавались без корректного представления; CSS-отступы нельзя восстановить строкой | Строки экранируются; четыре отступа передаются именованной таблицей `top/right/bottom/left` |
| Фоновая графика в игровом режиме | Визуализатор и дрейфующие фигуры продолжали обновляться | В игровом режиме визуализатор освобождает подписку, а покадровое обновление фигур останавливается |

Обычный режим сохраняет качество отрисовки, эффекты, частоту обновления и тайминги
анимаций. Существующий игровой режим остаётся отдельным переключателем: он
временно отключает часть эффектов. Живые обои уже приостанавливаются в игровом
режиме, при выключенном выходе и согласно выбранной политике полноэкранных окон.

## Проверки

Полный набор модульных проверок: 149 тестов. Проверки используют отдельные
конфигурации и подставные системные шины для сетевых, VPN и дисковых операций.
Исправлена зависимость сборки теста каталога приложений от QtGui.

Интеграционные сценарии:

- Построение всех основных страниц навигации и специализированных страниц
  сети, VPN, устройств, панели, ввода, буфера обмена и восстановления сессии.
- Поиск, раскрытие разделов, сохранение прокрутки, узкая компоновка, высокий
  контраст, уменьшение движения и быстрые последовательные переходы.
- Анимации и мембрана дока, нажатия по поднятым иконкам, превью, закрытие меню
  и истории буфера обмена по нажатию снаружи.
- Холст, указатель, прокрутка, Qt Quick, GTK, Wayland и XWayland, совместные
  позиции окон и захват окон за пределами координат монитора.
- Запуск `.desktop`, жизненный цикл процесса после завершения GIO,
  наблюдение за каталогом приложений, темы GTK и оформление оболочки.
- 201 последовательный ответ вспомогательного сервиса, добавление запроса
  из callback, ошибочный код выхода и восстановление после отсутствующего файла.
- Замены снимка сессии через atomic rename, изменение содержимого, временно
  повреждённый JSON, восстановление после ошибки, удаление файла и простой.
- Чтение обоих форматов Hyprland IPC и рабочих значений Lua, передача строк и
  четырёхсторонних отступов; включение/выключение игрового режима и reload
  настоящего вложенного Hyprland с восстановлением исходных значений.
- Отмена гибернации после подключения зарядки и восстановления заряда.
- Печать через отдельный виртуальный IPP-принтер: создание, пауза, продолжение,
  выбор по умолчанию, задания и проверка прав. Временная очередь удаляется,
  прежний принтер по умолчанию восстанавливается.

При первом общем прогоне найдены повреждённые Python bytecode-кэши. Повторный
прогон выполнен с отдельным `PYTHONPYCACHEPREFIX`. Первое выполнение проверки
оформления превысило таймаут; повтор после завершения сборок и исправления
наблюдения за сессиями прошёл. Ошибки исследованы, а не исключены из результатов.

Эти проверки не доказывают отсутствие всех багов. Все реальные серверы VPN,
модели устройств, сторонние плагины и игры требуют своих сценариев. Изменение
каждого системного переключателя на рабочей машине не входило в безопасный
прогон: опасные операции проверяются на подставных шинах или временных объектах.

## Измерение нагрузки

В репозитории добавлен инструмент без изменения конфигурации:

```bash
python3 distribution/profile_shell.py --seconds 10
```

Он находит процесс оболочки в `hic-session.service`, измеряет CPU относительно
одного ядра и RSS, обнаруживает смену процесса во время измерения. Длительность
ограничена 1–60 секундами. Для сравнения нужно сохранять одинаковые обои,
открытые окна, положение курсора и состояние панелей; перезапуск и холодный кэш
влияют на результат. Проценты CPU не являются измерением FPS игры.

Два контрольных замера по 10 секунд с теми же видеообоями 4K:

| Замер | CPU, % одного ядра | RSS, МиБ |
| --- | ---: | ---: |
| До установки | 13.6 | 1344.47 |
| После установки | 11.5 | 1118.52 |

После установки процесс перезапущен, а кэши и активность рабочего стола
различаются. Эти замеры фиксируют наблюдавшуюся нагрузку; приписывать всю разницу
исправлениям нельзя.

Для фонового мониторинга число внешних команд сокращено с четырёх до одной
на цикл: это сокращение запусков на 75% для данного монитора, а не всей нагрузки
оболочки. Сканирование снимков по таймеру удалено полностью.

## Оптимизация игр

1. **Сначала измерить время кадра.** Сравнивать одну сцену с одинаковыми
   настройками, 1% low, графиком времени кадра и загрузкой GPU/CPU. Выбирать
   изменения по результатам повторных замеров, а не только среднему FPS.
2. **Использовать исправленный игровой режим hics.** Он приостанавливает обои,
   визуализатор и фоновую анимацию фигур, временно меняет эффекты композитора.
   Выход восстанавливает рабочие параметры без reload всего сеанса:

   ```bash
   hics shell gameMode enable
   hics shell gameMode disable
   ```

3. **Feral GameMode для процесса игры.** После установки `gamemode` и нужных
   32-битных библиотек вариант запуска Steam — `gamemoderun %command%`.
   Этот сервис управляет системными параметрами и приоритетами; переключатель
   hics управляет оболочкой. Это разные уровни оптимизации. Настройки governor
   и приоритетов требуют замеров на конкретной машине.
   [Документация GameMode](https://github.com/FeralInteractive/gamemode/blob/master/README.md).
4. **Прямой вывод — отдельная проверка полноэкранной игры.** Параметр
   `render.direct_scanout = 2` выбирает автоматический режим для игрового
   типа содержимого. Результат зависит от драйвера, оверлеев и захвата экрана;
   при артефактах следует вернуть прежнее значение.
   [Параметры Hyprland](https://wiki.hypr.land/configuring/core/config-options/).
5. **VRR и tearing выбирать отдельно.** Сначала проверить поддержку VRR
   монитором и драйвером. Tearing может снижать задержку ценой разрывов;
   `allow_tearing` является разрешением, а не гарантией включения для всех игр.
   Сохранённая частота монитора остаётся 164,998 Гц.
   [Tearing в Hyprland](https://wiki.hypr.land/configuring/extra/tearing/).
6. **Профиль производительности — на время игры.** Сравнить доступный аппаратный
   профиль через настройки питания; следить за температурой и устойчивой
   частотой. Разгон не является обязательной оптимизацией оболочки.

VRR, direct scanout, параметры драйвера и профили питания не переключаются
глобально этим обновлением: для них нужны сравнения на реальных играх. На момент
аудита `gamemoderun`, MangoHud и Gamescope на машине не установлены. Прирост FPS
этим аудитом не измерен.

## Дополнительная оптимизация, 24 октября: пакет 1.1.1-31

Повторное профилирование по потокам показало около 4,7% одного ядра у потока
отрисовки видеообоев и 4,6% у GUI в одном десятисекундном замере. Декодирование
использует CUDA. Ограничение FPS или снижение разрешения видео не применялись.

Изменения:

- Каталог приложений повторно использует разобранные данные неизменённых файлов.
  Сверяются путь, размер, время изменения и изменения метаданных; событие
  наблюдения за файлом принудительно инвалидирует его запись.
- Изменения доступности `TryExec` проверяются отдельно. Переход между системным
  ярлыком и пользовательским переопределением учитывает исходный путь файла.
  Обновление списка происходит только при изменении записей или состава.
- Полное принудительное обновление доступно через `ApplicationCatalogue.refresh(true)`.
  Обычное обновление и страховочный опрос сохраняют прежнюю периодичность.
- Устранено обращение к уже уничтоженному окну у иконок рабочих пространств
  во время анимации удаления: в журнале рабочего сеанса обнаружен `TypeError`.
- Счётчик кадров обоев перенесён в C++. Статистика читается раз в секунду;
  покадровый обработчик JavaScript удалён. Частота вывода кадров сохранена.
- Повторная публикация неизменившихся состояний движка и приостановленного видео
  не запускает зависимые QML-выражения.
- Для фона с непрозрачной чёрной основой выставлен признак непрозрачной поверхности.
  Прозрачный фон Wallpaper Engine сохраняет прозрачную поверхность.

Сравнение исходного и нового каталога: одинаковая небольшая программа, сборка
`-O2`, 500 ярлыков, 30 обновлений в каждом запуске, три запуска каждой версии:

| Показатель | До | После |
| --- | ---: | ---: |
| Медиана времени 30 обновлений | 388,68 мс | 194,59 мс |
| Уведомления об изменении неизменённого каталога | 30 | 0 |

Это примерно двукратное ускорение **обновления каталога**, а не всей оболочки.
Проверены создание, изменение и удаление ярлыков, запуск GIO, доступность TryExec,
системные и пользовательские переопределения, изменения действий ярлыка,
пауза/продолжение/перезапуск видео и восстановление декодера. Счётчик C++ сверяется
с реально полученными кадрами. Интеграционная проверка подтверждает, что
неизменившийся статус обоев не публикуется повторно, а новые кадры видны.

Снижение постоянного RSS этим сравнением не доказано: добавленный небольшой кэш
сокращает повторный разбор и перестроение моделей, а не заменяет память декодера.

## Сокращение фоновой работы — 25 октября 2026, пакет 1.1.1-54

Сеть переведена на один асинхронный `NMClient` libnm в собственном GLib-контексте.
`Nmcli.qml` оставлен как совместимый интерфейс для виджетов: он больше не запускает
процессы. Оба `nmcli monitor` удалены. Профили, точки доступа и состояние устройств
обновляются по сигналам; статистика интерфейсов читается через QFile. Изменения
профилей клонируют прежние настройки, сохраняя IPv6 и неизвестные расширения.
Завершение сервиса отменяет операции и дожидается освобождения контекста libnm.

История уведомлений больше не создаёт скрытые PanelWindow, процессы и таймеры для
каждой записи. Оставлены общая очередь действий, общий таймер истечения и привязки
только живых уведомлений. Изображения сохраняются в C++ через ограниченную очередь
QImageReader; исходные снимки копируются без перекодирования. Проверяются размеры
файлов, изображений и очереди. Wayland-окна для этого не создаются.

Дополнительно:

- Анализ обоев включается только при прозрачности; загружается только выбранный
  поисковый движок. Его кэши ограничены и очищаются при выгрузке.
- Поиск приложения по классу/ID имеет ограниченный C++-кэш, включая отсутствующие
  приложения. Каталог инвалидирует его при сканировании; обработка тем иконок
  сохранена в Quickshell, чтобы не закреплять устаревшие пути после смены темы.
- Обновление цветов передаёт правила и Lua-вызовы одним IPC-пакетом.
- Overview получает снимки через сокет HyprExtras по событиям, без запуска hyprctl
  каждые 500 мс. Отдельный лёгкий heartbeat сохраняет нативную защиту от зависшего UI.
- Обнаружение DDC использует sysfs и отпечаток подключённых экранов, без автоматического
  `ddcutil detect`. Apple-хелпер проверяется только для Studio Display.
- Вместо слушателя мыши у каждого заголовка используется один маршрутизатор.
  Захваченный курсор и блокировка сессии проверяются до поиска окна/монитора.
- В полноэкранном игровом режиме дерево основных панелей и дополнительные панели
  выгружаются. Явно вызванное меню возвращается и закрывается обычным способом.
  Изменения состояния отложены до конца обработки события, чтобы избежать гонок
  фокуса при уничтожении окна. Это убирает препятствие для scanout со стороны этих
  слоёв, но не гарантирует аппаратный scanout на любом драйвере.
- Интервал телеметрии умножается на пять; резервный CLI-опрос NVIDIA во время игры
  пропускается. Уже существующий изолированный NVML-хелпер сохранён: зависание
  драйвера не должно блокировать GUI. Прежние настройки питания и GameMode сохранены.
- Автоматическое снижение ступени памяти и drain приостановлены на время игры.
  Маркер привязан к UID, живому PID и времени его запуска; оставшийся после падения
  файл не удерживает память. Рост при нехватке памяти продолжает работать.
- Кнопка домашнего каталога использует `$HOME` текущего пользователя.

### VRAM: исправление оценки и границы оптимизации

Gaussian blur использует ping-pong вместо отдельного вертикального буфера.
После выхода из обзора промежуточные буферы освобождаются. Для линейного рабочего
пространства кэш хранится в четверти разрешения и растягивается билинейно.
Для нелинейного пространства сохраняется полноразмерный encode-проход: в Hyprland
0.56.2 метаданные текстуры могут игнорироваться при выключенном CM или
`doesNoShaderCM()`, поэтому простая подстановка линейной текстуры меняет цвета.
Для HDR также сохранён порядок «линейное увеличение → encode».

Расчёт для 3840×2160 FP16, только этих буферов (не всей VRAM композитора):

| Состояние | Раньше | Теперь, линейный источник | Теперь, нелинейный источник |
| --- | ---: | ---: | ---: |
| Пик построения blur | 95,39 MB | 24,88 MB | 91,24 MB |
| Кэш после закрытия | 95,39 MB | 4,15 MB | 66,36 MB |

Таким образом, универсальное обещание «в 7,5 раза» неверно. Изменения не ограничивают
FPS, разрешение обоев, качество Gaussian или обычные анимации. Общий выигрыш RSS/CPU
и FPS зависит от системы; проценты для всей оболочки этим набором тестов не измерены.

Проверки включают настоящий libnm на частной D-Bus с 30 Wi-Fi-профилями, изменение
точки доступа сигналом, ошибки прав, сохранение IPv6, отмену запуска/запросов;
копирование и уменьшение картинок без окон; оба поисковых движка; смену/удаление
.desktop и инвалидирование поиска; страницы настроек и уведомления; реальные
указательные события дока; перетаскивание CSD/SSD; выход из fullscreen при изменении
резервов дока; выгрузку/возвращение слоёв в игре; нативный обзор и повторное использование
blur. Графические сценарии выполняются во вложенном композиторе, не в рабочей сессии.

Основания: [NMClient](https://www.networkmanager.dev/docs/libnm/latest/NMClient.html),
[QQuickImageProvider](https://doc.qt.io/qt-6/qquickimageprovider.html),
[QsWindow](https://quickshell.org/docs/v0.2.1/types/Quickshell/QsWindow/),

## Повседневные сценарии DE — 25 октября 2026, пакет 1.1.1-55

### Публичный Wi-Fi

Единый NMClient публикует Connectivity, доступность/состояние проверки и её URI.
При PORTAL появляется кнопка входа в сетевых настройках и быстром меню; по умолчанию
помощник открывается автоматически один раз для подключения. Это можно отключить.
При полном доступе окно закрывается. Повторная проверка асинхронная; опрос раз в
10 секунд работает только пока требуется авторизация.

`hics-portal` — отдельный C++/WebKitGTK-процесс. Сеанс WebKit временный, cookies не
попадают в основной браузер и не переживают закрытие. Есть адресная строка для
проверки домена, повтор загрузки и пользовательские окна авторизации. Локальные
схемы, загрузка файлов и разрешения камеры/микрофона запрещены, ошибки TLS не
игнорируются. Библиотеки приватного Qt не передаются внешним GTK-программам.
Проверка NetworkManager использует настроенный в системе адрес (Arch поставляет
свой connectivity-конфиг); отсутствие адреса явно показано в интерфейсе.

### Ноутбук и звук

У блокировки, выключения экранов и suspend появились отдельные задержки от батареи
и от сети. Ноль отключает действие для выбранного питания; старые конфигурации
сохраняют общую задержку до явного изменения. Действуют существующие исключения
для воспроизведения/зарядки и lock-before-sleep.

Опция док-станции держит низкоуровневый `handle-lid-switch` inhibitor logind только
при внешнем экране и активной сессии пользователя. При отключении экрана, смене
сессии, выключении опции и завершении оболочки FD освобождается. Ответы старого
экземпляра logind не могут восстановить inhibitor после смены владельца D-Bus.
`logind.conf` не меняется. Закрытие настоящей крышки физического ноутбука в тестах
не имитировалось: проверены транспорт FD и переходы активности на частном D-Bus.

Баланс меняет только FL/FR, не переупорядочивает остальные каналы. Существующий
настраиваемый лимит усиления теперь применяется к ползункам настроек и быстрого
меню. Отдельный переключатель выставляет удобные 150%; предупреждение об искажениях
видно рядом. Проверка динамиков генерирует плавно затухающий короткий тон отдельно
в левом/правом канале через QAudioSink. Звук тестировался в частном PipeWire,
включая баланс, усиление, оба тестовых канала и восстановление мьюта.

### Очистка и передача файлов

В накопителях есть карточка свободного места: открыть/очистить корзину, оценить
домашнюю корзину и миниатюры, удалить старые миниатюры, включить их ежедневную
автоочистку с настраиваемым сроком. Автоочистка по умолчанию выключена. Корзина
очищается GIO, только после отдельного подтверждения; учитываются и подключённые
корзины, хотя оценка размера охватывает домашний том.

Для кэша пакетов брокер запускает фиксированный `paccache -r -k3`, для старых дампов
— `systemd-tmpfiles --clean --prefix=/var/lib/systemd/coredump`. Последний соблюдает
системные сроки хранения; свежие дампы не удаляются произвольно. Задачи systemd
работают с низким приоритетом и ограничением записи; их результат виден в карточке.
Можно включить штатный paccache.timer. Требуется обычная авторизация polkit.
Произвольные пути/команды не принимаются. При отсутствии paccache функция недоступна.
Очистка миниатюр использует openat/O_NOFOLLOW и unlinkat относительно открытых FD,
ограничивает глубину/число записей и не следует символическим ссылкам.
Проверки очистки выполняются на временных файлах и частной D-Bus-модели, а не на
пользовательской корзине/пакетах/дампах.

Bluetooth-страница запускает установленный помощник Blueman для выбора файлов и
приёма OBEX; подтверждение передачи приходит через обычные уведомления оболочки.
Blueman и bluez-obex включены в Arch-зависимости. LocalSend и KDE Connect доступны
как интеграции с установленными приложениями; они остаются необязательными
зависимостями. Собственный OBEX-стек вместо Blueman не заявляется. Передача на
физический телефон не проверена без устройства-получателя.

### Приватность

Общий мьют затрагивает все PipeWire-микрофоны, включая вновь появившиеся, и
противодействует попытке приложения снять мьют. Настройка и предыдущие состояния
сохраняются; после отключения режима возвращаются прежние значения. Быстрый доступ
и страница трансляции показывают входящие аудиопотоки и уже существующий список
видеозахвата; индикатор панели учитывает и микрофон.

Камера: переключатель отключает оба монитора WirePlumber — V4L2 и libcamera — через
отдельный управляемый конфиг. Перезапуск WirePlumber прерывает звук на короткое время,
о чём интерфейс предупреждает. Ошибка применения возвращает прежний конфиг.
**Это блокировка PipeWire, не аппаратный и не общесистемный запрет:** прямой
доступ к /dev/video или ALSA и привилегированные программы не являются её областью.
Для аппаратной гарантии требуется шторка/переключатель устройства. Эти настройки
также не подменяют полноценный родительский контроль учётных записей.

Исправлена дополнительная регрессия общего таймера уведомлений: обработчики
наведения/перетаскивания теперь вызывают pauseExpiry/resumeExpiry, а не удалённый
таймер отдельной записи. Уведомление под указателем не исчезает по таймауту.

Основания: [NMClient](https://www.networkmanager.dev/docs/libnm/latest/NMClient.html),
[logind inhibitors](https://systemd.io/INHIBITOR_LOCKS/),
[WirePlumber camera configuration](https://pipewire.pages.freedesktop.org/wireplumber/daemon/configuration/video.html),
[Blueman transfer service](https://github.com/blueman-project/blueman/blob/master/blueman/plugins/applet/TransferService.py),
[WebKit ephemeral network sessions](https://webkitgtk.org/reference/webkitgtk/stable/ctor.NetworkSession.new_ephemeral.html).

Проверка релиза 55: 262 автоматических теста, ошибок нет (199,02 с).
Реальные страницы настроек и быстрые меню прошли проверку без TypeError,
ReferenceError и циклов привязок. Отдельно проверены WebKit, частный PipeWire
и передача inhibitor FD через D-Bus. Nix-описание зависимостей обновлено;
сборка Nix в этой среде не выполнялась.

Дополнительная проверка на реальном входящем аудиопотоке использует явный
PwNodeType.AudioInStream: направление isSink у stream-узлов Quickshell нельзя
трактовать как направление аппаратного входа. Проверены показ приложения захвата
и отсутствие включения обычного playback-потока в список микрофонов.


## Существующее хранилище секретов — пакет 1.1.1-56

На проверяемой системе владельцем org.freedesktop.secrets является GNOME Keyring,
коллекция по умолчанию — login, на момент проверки разблокирована. KWallet установлен,
но этот D-Bus-интерфейс не обслуживает. Проверены только имя владельца, тип сервиса,
путь коллекции и флаг Locked; значения секретов не запрашивались.

VPN SecretAgent уже использует libsecret. Arch-пакет теперь явно зависит от
`gnome-keyring`, поскольку одной клиентской библиотеки libsecret недостаточно для
гарантированного наличия сервиса на чистой системе. Nix-пакет включает провайдер,
а NixOS-модуль по умолчанию включает штатный services.gnome.gnome-keyring;
явный пользовательский выбор сохраняет приоритет над mkDefault.

Новый формат базы, криптография, перенос/перешифрование секретов и отдельный
конкурирующий демон не добавляются. Существующий сервис не перезапускается и
коллекции не меняются. Настройки PAM в Arch не редактируются: автоматическая
разблокировка относится к способу входа, а не к запуску графической оболочки.
При автоматическом входе без пароля отдельный запрос разблокировки может быть
необходимым и не должен обходиться созданием незащищённой коллекции.

Документация: [libsecret](https://gnome.pages.gitlab.gnome.org/libsecret/),
[GNOME Keyring и PAM](https://wiki.gnome.org/Projects/GnomeKeyring/Pam),
[штатный модуль NixOS](https://github.com/NixOS/nixpkgs/blob/master/nixos/modules/services/desktops/gnome/gnome-keyring.nix).
